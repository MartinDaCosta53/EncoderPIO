# EncoderPIO

## Overview

EncoderPIO reads 1 to 4 quadrature rotary encoders on an RP2040 or RP2350 using the PIO hardware. Each encoder gets its own state machine, which decodes edges without CPU involvement. A small interrupt handler then turns the decoded steps into a position counter.

| File | Role |
| --- | --- |
| `EncoderPIO.pio.h` | The compiled PIO program (generated by `pioasm`, never edited by hand) |
| `EncoderPIO.h` | Class declaration and public API |
| `EncoderPIO.cpp` | Setup, interrupt handling and counting logic |

## EncoderPIO.pio.h: the PIO program

The state machine continuously samples the two encoder pins and combines the previous pin state (2 bits) with the new state (2 bits) into a 4-bit number, `v = (old << 2) | new`. It uses `v` as an index into a 16-entry jump table, so no comparison logic is needed.
Valid changes are pushed to the State Machines Rx FIFO which causes an interrupt to be raised.

## EncoderPIO.h: the class

One `EncoderPIO` object drives 1 to 4 encoders on a single PIO block, with one state machine per encoder.

### Design rules

- One `EncoderPIO` object per PIO block (2 on RP2040, 3 on RP2350).
- Each encoder is identified by its A pin, and **B must be on the next GPIO.**
- Encoder indices follow constructor order: 0 is the first pin, 1 the second, and so on.

### Public methods

| Method | What it does |
| --- | --- |
| Constructors (1 to 4 pins) | Store the PIO number and pin(s). They do no hardware work yet |
| `initialiseEncoder()` | Claims and configures the hardware. Returns `true` or `false` |
| `getPosition([enc])` | Current position. Returns 0 for an invalid index |
| `setPosition([enc,] pos)` | Sets the position, clamped to the limits |
| `setLimits([enc,] min, max)` | Sets the range. Returns `false` if `max <= min` or the index is bad |
| `setWrap([enc,] bool)` | Whether the position wraps around at the limits or stops there |
| `setCountsPerDetent([enc,] n)` | Number of edges that make up one step |

The overloads without an `enc` argument are inline wrappers that use encoder 0, so single-encoder code stays simple.

## Things to note

- Direction: if the encoder counts backwards, swap the A and B wires.
- Multi-core: `save_and_disable_interrupts()` only masks interrupts on the calling core. If you call the setters from a different core than the one that ran `initialiseEncoder()`, the protection will not apply.
- Header vs. code mismatch: the header comment says counts per detent is 1, 2 or 4, but the code accepts 1 to 100.
- No destructor: there is no way to release the state machines or the PIO program once initialised.
- RP2350 high GPIOs: the code does not set a PIO GPIO base (yet), so pins above 31 on RP2350B will not work as written.
